
```
❌ ОШИБКА: Пытаться делать OAuth2-запрос через fetch()
   OAuth2 — это РЕДИРЕКТ БРАУЗЕРА, не AJAX-запрос.
   Используй window.location.href, а не fetch().

❌ ОШИБКА: Забыть обработать callback-страницу
   После OAuth2 пользователя кидает обратно на твой сайт.
   Нужна страница, которая подхватит токены из URL.

❌ ОШИБКА: Отвязать единственный способ входа
   Если у пользователя нет пароля и привязан только Google —
   нельзя отвязать Google (иначе он вообще не сможет войти).
   Бэкенд обычно кидает ошибку в этом случае.
```

# WebAuthn и OAuth2 — объяснение для фронтенда

---

## OAuth2 (вход через Google, GitHub и т.д.)

### Что это вообще такое

OAuth2 — это когда пользователь нажимает кнопку «Войти через Google» и ему НЕ нужно придумывать пароль для твоего сайта. Вместо этого:

1. Пользователь нажимает кнопку
2. Его кидает на страницу Google
3. Google спрашивает «Разрешить сайту XYZ доступ к вашему профилю?»
4. Пользователь нажимает «Разрешить»
5. Google кидает пользователя обратно на твой сайт с секретным кодом
6. Твой бэкенд берёт этот код, идёт с ним к Google, получает данные пользователя
7. Бэкенд создаёт аккаунт (или находит существующий) и возвращает токены

### Как это выглядит на фронте

**Весь OAuth2-флоу начинается с обычной ссылки. Бэкенд сам всё делает. Тебе нужно буквально сделать ссылку или редирект.**

#### Шаг 1: Кнопка «Войти через Google»

HTML

```
<!-- Самый тупой вариант — обычная ссылка -->
<a href="/oauth2/authorization/google">Войти через Google</a>
<a href="/oauth2/authorization/github">Войти через GitHub</a>
<a href="/oauth2/authorization/yandex">Войти через Яндекс</a>
```

Или через JavaScript:

JavaScript

```
function loginWithGoogle() {
  // Просто перенаправляем браузер. Всё.
  window.location.href = '/oauth2/authorization/google';
}
```

HTML

```
<button onclick="loginWithGoogle()">Войти через Google</button>
```

#### Что происходит после нажатия

text

```
Пользователь нажал кнопку
        │
        ▼
Браузер уходит на /oauth2/authorization/google
        │
        ▼
Spring Boot перехватывает и редиректит на Google
        │
        ▼
Пользователь видит страницу Google: "Разрешить доступ?"
        │
        ▼
Пользователь нажал "Разрешить"
        │
        ▼
Google редиректит обратно на твой сайт:
/login/oauth2/code/google?code=СЕКРЕТНЫЙ_КОД
        │
        ▼
Spring Boot ловит этот запрос, идёт к Google с кодом,
получает данные, создаёт/находит пользователя
        │
        ▼
Spring Boot редиректит на фронтенд с токенами
(обычно что-то типа /oauth2/success?token=xxx)
        │
        ▼
Фронтенд забирает токены из URL и сохраняет
```

#### Шаг 2: Поймать токены после редиректа

После успешного OAuth2-входа бэкенд обычно редиректит на определённый URL с токенами. Как именно — зависит от настроек бэкенда. Обычно варианты такие:

**Вариант А: Токены в URL (query параметры)**

JavaScript

```
// Страница /oauth2/success
// URL выглядит как: /oauth2/success?accessToken=xxx&refreshToken=yyy

const params = new URLSearchParams(window.location.search);
const accessToken = params.get('accessToken');
const refreshToken = params.get('refreshToken');

if (accessToken) {
  localStorage.setItem('accessToken', accessToken);
  localStorage.setItem('refreshToken', refreshToken);
  
  // Убираем токены из URL (чтобы не светились в истории браузера)
  window.history.replaceState({}, '', '/');
  
  // Редирект на главную
  window.location.href = '/dashboard';
}
```

**Вариант Б: Токены во фрагменте URL (после #)**

JavaScript

```
// URL: /oauth2/success#accessToken=xxx&refreshToken=yyy

const hash = window.location.hash.substring(1); // убираем #
const params = new URLSearchParams(hash);
const accessToken = params.get('accessToken');
const refreshToken = params.get('refreshToken');

if (accessToken) {
  localStorage.setItem('accessToken', accessToken);
  localStorage.setItem('refreshToken', refreshToken);
  window.location.href = '/dashboard';
}
```

### Привязка OAuth2 к существующему аккаунту

Допустим, пользователь уже зарегистрировался по email/паролю, а теперь хочет ПРИВЯЗАТЬ Google, чтобы потом входить через него.

JavaScript

```
function linkGoogle() {
  // Тот же редирект, но бэкенд знает, что пользователь уже залогинен,
  // и привязывает Google-аккаунт к существующему
  window.location.href = '/oauth2/authorization/google';
}
```

HTML

```
<button onclick="linkGoogle()">Привязать Google</button>
```

### Полный пример страницы настроек OAuth2

HTML

```
<h2>Привязанные аккаунты</h2>
<div id="linked-accounts"></div>

<h3>Привязать новый</h3>
<button onclick="window.location.href='/oauth2/authorization/google'">
  Привязать Google
</button>
<button onclick="window.location.href='/oauth2/authorization/github'">
  Привязать GitHub
</button>

<script>
async function loadAccounts() {
  const response = await fetch('/api/users/me/oauth2', {
    headers: {
      'Authorization': `Bearer ${localStorage.getItem('accessToken')}`
    }
  });
  
  const accounts = await response.json();
  const container = document.getElementById('linked-accounts');
  
  if (accounts.length === 0) {
    container.innerHTML = '<p>Нет привязанных аккаунтов</p>';
    return;
  }
  
  container.innerHTML = accounts.map(acc => `
    <div style="margin: 10px 0; padding: 10px; border: 1px solid #ccc;">
      <strong>${acc.provider.toUpperCase()}</strong>
      <br>Email: ${acc.providerEmail}
      <br>Привязан: ${new Date(acc.linkedAt).toLocaleDateString()}
      <br>
      <button onclick="unlinkAccount('${acc.provider}')">
        Отвязать
      </button>
    </div>
  `).join('');
}

async function unlinkAccount(provider) {
  if (!confirm(`Отвязать ${provider}?`)) return;
  
  await fetch(`/api/users/me/oauth2/${provider}`, {
    method: 'DELETE',
    headers: {
      'Authorization': `Bearer ${localStorage.getItem('accessToken')}`
    }
  });
  
  // Перезагрузить список
  loadAccounts();
}

// При загрузке страницы
loadAccounts();
</script>
```

## WebAuthn (вход по отпечатку пальца / Face ID / USB-ключу)

### Что это вообще такое

WebAuthn — это стандарт, который позволяет входить без пароля, используя:

- **Отпечаток пальца** (Touch ID на MacBook, сканер на телефоне)
- **Распознавание лица** (Face ID, Windows Hello)
- **USB-ключ** (YubiKey, Titan Security Key)
- **Bluetooth-ключ**
- **PIN-код устройства** (Windows Hello PIN)

Суть: вместо пароля, который можно украсть/подобрать, используется криптографический ключ, который хранится в железе устройства и НИКОГДА не покидает его.

### Как это работает (простыми словами)

text

```
РЕГИСТРАЦИЯ КЛЮЧА (один раз):

1. Ты говоришь серверу: "Хочу добавить отпечаток пальца"
2. Сервер говорит: "Ок, вот тебе случайная задачка (challenge)"
3. Браузер показывает диалог: "Приложите палец"
4. Пользователь прикладывает палец
5. Устройство создаёт пару ключей (публичный + приватный)
6. Приватный ключ остаётся В УСТРОЙСТВЕ (никуда не отправляется!)
7. Публичный ключ отправляется на сервер и сохраняется
8. Готово! Теперь можно входить по пальцу.

ВХОД ПО КЛЮЧУ (каждый раз):

1. Ты говоришь серверу: "Хочу войти по отпечатку"
2. Сервер говорит: "Ок, подпиши эту случайную задачку (challenge)"
3. Браузер показывает диалог: "Приложите палец"
4. Пользователь прикладывает палец
5. Устройство подписывает задачку приватным ключом
6. Подпись отправляется на сервер
7. Сервер проверяет подпись публичным ключом
8. Если подпись верная — пользователь залогинен!
```

### Важно понимать

text

```
Пароль:   можно украсть, подсмотреть, подобрать, слить из базы
WebAuthn: приватный ключ НИКОГДА не покидает устройство
          даже сервер его не знает
          даже если базу сервера сольют — ключи бесполезны
```
