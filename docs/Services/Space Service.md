#### 3. Space Service (VoIP / Streaming)

Самый изолированный модуль, но требует синхронизации статусов.

- **Ответственность:**
    - Управление "комнатами" (создание, удаление, настройки прав).
    - **Signaling (Сигналинг):** Обмен SDP (Session Description Protocol) и ICE кандидатами для установки WebRTC соединения.
    - Управление "Спотифай-вечеринками" (синхронизация прослушивания).
- **Технологии:**
    - Spring WebFlux (для работы с большим количеством открытых соединений).
    - WebSocket (отдельный эндпоинт для сигналинга).
    - _Важно:_ Сам медиа-трафик (аудио/видео) идет P2P или через отдельный Media Server (например, Mediasoup/Janus), этот сервис только управляет метаданными.
- **Хранение данных:**
    - Таблицы: `spaces`, `space_members`, `space_settings`.
    - Redis: Хранение текущего состояния комнаты (кто говорит, кто мьютнут).
- **Интеграция:**
    - **Зависимость:** Identity (проверка прав входа в комнату).
    - **Взаимодействие:** При входе в Voice Room отправляет статус в Messaging Service (плашка "Говорит в Space X").

Дополнительные-вспомогательные сервер+сервис:
#### Signaling Server (Signaling Service)

- **Роль:** Он — "таможня" и "сват". Он не трогает груз (видео), он договаривается о встрече.
- **Что делает:**
    - Управляет WebSocket-подключениями.
    - Создает "Комнаты" (Rooms).
    - Проверяет права (может ли юзер говорить? Есть ли у него микрофон?).
    - **Обменивается SDP (Session Description Protocol):** Это метаданные. Клиент А говорит: "Я умею кодировать видео в H264, вот мой IP". Клиент Б говорит: "Ок, я умею принимать H264".
    - Как только стороны договорились, Signaling Server отходит в сторону.

#### Media Server (SFU - Selective Forwarding Unit)

_Это внешний сервер (программа), который ставится рядом._

- Примеры: **Mediasoup, Janus, Jitsi Videobridge**.
- **Роль:** Это "почтовое отделение" для видео/аудио.
- **Как работает:**
    1. Клиент А шлет видео на IP Media Server'а.
    2. Media Server принимает поток.
    3. Пересылает его Клиенту Б, Клиенту В, Клиенту Г.

### 3.1. Структура и Управление (Management)

#### Таблица: `voice_rooms` (Голосовые комнаты)

Это "физические" комнаты внутри Группы. Создаются, когда владелец группы включает функцию голоса.

|Поле|Тип данных|Описание|
|---|---|---|
|**id**|`BIGSERIAL`|Primary Key (PK).|
|**group_id**|`BIGINT`|FK на таблицу `groups` в Messaging Service.|
|**name**|`VARCHAR(50)`|Название комнаты ("General", "Gaming").|
|**position**|`INTEGER`|Порядок сортировки в списке (как в текстовых каналах).|
|**bitrate**|`INTEGER`|Максимальный битрейт (качество звука), например 64000.|
|**max_users**|`INTEGER`|Лимит участников (0 = без лимита).|
|**created_at**|`TIMESTAMPTZ`|Дата создания.|

#### Таблица: `room_permissions` (Настройка прав)

Позволяет гибко настраивать, кто может говорить в конкретной комнате (аналог Discord Overwrites).

|Поле|Тип данных|Описание|
|---|---|---|
|**id**|`BIGSERIAL`|PK.|
|**room_id**|`BIGINT`|FK на `voice_rooms`.|
|**target_type**|`VARCHAR(20)`|Кого касается правило: `ROLE` (роль) или `USER` (юзер).|
|**target_id**|`BIGINT`|ID роли или ID пользователя.|
|**allow_speak**|`BOOLEAN`|Может ли говорить.|
|**allow_stream**|`BOOLEAN`|Может ли включать камеру/экран.|
|**allow_join**|`BOOLEAN`|Может ли входить в комнату вообще.|

### 3.2. Runtime State (Текущее состояние)

Эти таблицы могут быть вынесены в Redis для скорости, но если нужна надежность и история — держим в Postgres и кэшируем.

#### Таблица: `voice_sessions` (Кто сейчас в комнате)

Отображает текущее присутствие пользователей. Запись создается при входе и удаляется при выходе.

|Поле|Тип данных|Описание|
|---|---|---|
|**id**|`BIGSERIAL`|PK.|
|**room_id**|`BIGINT`|FK на `voice_rooms`.|
|**user_id**|`BIGINT`|ID пользователя.|
|**muted**|`BOOLEAN`|Выключен ли микрофон.|
|**deafened**|`BOOLEAN`|Выключен ли звук у него.|
|**video_enabled**|`BOOLEAN`|Включена ли камера.|
|**screen_enabled**|`BOOLEAN`|Включен ли шаринг экрана.|
|**joined_at**|`TIMESTAMPTZ`|Время входа. Индекс.|

#### Таблица: `active_streams` (Активные трансляции)

Если у вас в комнате несколько человек стримят одновременно (или для Picture-in-Picture).

|Поле|Тип данных|Описание|
|---|---|---|
|**id**|`BIGSERIAL`|PK.|
|**session_id**|`BIGINT`|FK на `voice_sessions`.|
|**type**|`VARCHAR(20)`|`VIDEO` (камера) или `SCREEN` (экран).|
|**started_at**|`TIMESTAMPTZ`|Время начала стрима.|
