#### Поток 1: Фундамент (Identity Service)

- **Задача:** Развернуть базу, написать миграции, настроить Spring Security.
- **Результат:** Рабочий OAuth2 сервер, возможность зарегистрироваться и получить JWT.
- **Статус:** Блокирует остальные сервисы, делается в первую очередь (неделя 1).

#### Поток 2: Мессенджер (Messaging Service)

- **Когда начинать:** Как только в Identity есть возможность получить `userId` из токена.
- **Параллельность:** Разработчик пишет логику чатов. Для тестов можно мокать Identity Service (просто хардкодить ID пользователя), пока тот не готов полностью.
- **Независимость:** Не зависит от Музыки и Стриминга. Можно делать параллельно с ними.

#### Поток 3: Музыка (Media Service)

- **Когда начинать:** Сразу после настройки MinIO (S3).
- **Параллельность:** Абсолютно независим от Мессенджера.
- **Задача:** Реализовать загрузку файла, нарезку на куски (HLS), отдачу плейлиста.

#### Поток 4: Голосовые чаты (Space Service)

- **Когда начинать:** Можно стартовать параллельно с Messaging, но требует понимания WebSocket (который будет и в Messaging).
- **Сложность:** Требует изучения WebRTC протокола.
- **Изоляция:** Пишется как отдельный микросервис, общается с остальными только через события.

#### Поток 5: Уведомления (Notification Gateway)

- **Когда начинать:** В самом конце, когда есть события, которые нужно отправлять. Либо писать "заглушку" интерфейса в коде других сервисов (`NotificationService` interface), которую потом реализовать.
